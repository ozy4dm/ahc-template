# 利用者向けガイド

このリポジトリは、AHC の各大会で解答コードと実験を管理するための**作業用の雛形**です。大会の解法、公式ツール、入力データ、完成済みのビルド設定は含みません。使い始める前に、大会固有の条件を参加者が決めて設定します。

## 1. 大会用の作業場所を作る

このリポジトリを大会ごとに別のフォルダへ複製します。テンプレートそのものに大会固有の解法や実験結果を混ぜないようにします。`src/bin/` に解答コード、`cases/` に入力を置く想定です。問題文や公式ツールは参加者がブラウザで手動取得し、問題文 PDF は `local/problem.pdf`、公式ツールは `tools/` に置きます。共通スクリプトは `scripts/` にあります。`local/` と `tools/` は Git の管理対象から除外されています。取得元 URL と取得日を別途記録し、各配布物の公開条件を確認してください。

Python 3 が比較・スコアボードに必要です。実験一覧の表示は PowerShell スクリプトです。Rust は、この雛形を Rust 解答コードと Rust 製公式ツールで使う場合に必要です。これらのインストール方法やバージョンは大会・利用環境に合わせて確認してください。

## 2. AI 利用ルールを確認する

`AGENTS.md` には現時点のルール案に基づく AI 向け指示と全文があります。開催時に**その大会に適用される正式版**と照合し、相違があれば正確に更新します。Claude Code をリポジトリのルートで起動すると、`CLAUDE.md` が `@AGENTS.md` を読み込みます。Claude Code 内の `/context` で読み込みを確認してください。

`/ahc-rule-check ［依頼文］` は依頼文の事前点検です。依頼自体は実行しません。曖昧な依頼だけで参加者の違反を断定するものではなく、運営の最終判断にも代わりません。ほかの AI や独立したセッションを使う場合も、適用される必須指示をそれぞれに設定してください。

## 3. 大会固有の設定をする

`config.example.json` を `config.json` にコピーし、次を設定します。`config.json` は Git 管理から除外されています。

| キー | 設定内容 |
|---|---|
| `input_glob` | 比較する入力ファイルのパターン。例: `cases/dev/*.txt` |
| `time_limit_seconds` | ソルバー1回あたりの制限時間 |
| `scorer_time_limit_seconds` | 採点コマンドの制限時間 |
| `score_direction` | 小さいほど良ければ `lower`、大きいほど良ければ `higher` |
| `score_pattern` | 採点コマンドの出力から点数を抜き出す正規表現。最初の括弧が数値 |
| `solvers` | 版 ID と、その実行コマンドの対応 |
| `scorer` | 公式採点コマンド。`{input}` と `{output}` がファイルパスに置換される |

コマンドは文字列の配列で指定します。ソルバーは入力を標準入力から受け、標準出力へ解答を書きます。相対パスはリポジトリのルートから解決されます。Windows の実行ファイルには `.exe` を付けてください。採点結果の表示形式は大会ごとに異なるため、`score_pattern` は公式ツールの実際の出力で確認します。

公式 generator・tester・visualizer の配置、ソルバーのビルド、入力生成はこの雛形では自動化していません。`tools/` に置いた公式ツールを使うコマンドは大会ごとに用意します。

## 4. 実験を計画・実行する

1. 参加者が比較対象、ケース集合、seed、反復回数、時間制限、スコアの向き、採用基準を決めます。重要な判断は `docs/decisions.md` に記録します。
2. `docs/experiments/TEMPLATE.md` を `EXP-001-内容.md` のように複製し、**実行前**に条件を記入します。解法版は `docs/solutions.md` に記録します。
3. ケースの入力を `cases/dev/` などへ置き、`config.json` の `input_glob` を固定します。
4. ソルバーと公式採点ツールを準備してから、比較を実行します。

```text
python scripts/compare_solvers.py EXP-001 baseline candidate
```

結果は `reports/experiments/EXP-001/cases.csv` と `summary.json` に保存されます。同じ実験 ID のディレクトリがあると上書きを拒否します。途中で失敗した場合、完了済みケースを `cases.partial.csv` に残す場合があります。実験記録の「結果」「観察事項」は、保存された事実に基づいて記入します。結果から解法の改善方針を AI に考案させません。

この比較ツールは、指定した入力集合を各ソルバーで**1回ずつ**実行します。反復回数や seed を含む実験を行うときは、参加者が指定した方法でコマンド・入力集合を用意し、その条件と結果を別途記録してください。指定していない反復や候補探索をツールが自動で行うことはありません。

## 5. 保存済み結果を見る

```text
python scripts/show_scoreboard.py --direction lower
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/show_experiment_results.ps1
```

スコアボードの `--direction` は実験時の向きと合わせます。同一ソルバー・ケースに複数の成功結果があれば最良値を使い、全ケースの結果がそろった版だけを表示します。これは記録済みスコアの機械的な相対表示であり、解法の採用判断ではありません。実験一覧は `docs/experiments/EXP-*.md` を読み、`reports/experiment_results.csv` を更新します。

## 6. 公開とログ保存

テンプレートの Git 履歴は、設計や変更の経緯を追うためのものです。大会参加時の生成 AI 利用ログの代わりにはなりません。適用されるルールに従い、Claude Code を含む各 AI との対話と取得可能な作業ログを、提出可能な形で別途保存してください。公開前には、生成入力、解答出力、実験結果、認証情報、個人情報、公式配布物の扱いを確認します。

Claude Code の CLI には、現在の会話をテキストへ書き出す [`/export`](https://code.claude.com/docs/en/commands) があります。大会開始前に試験セッションで書き出しを行い、必要な入力・応答・取得可能なツール履歴をどこまで保存できるか確認してください。`/export` だけで提出対象を網羅するとは想定しません。

Claude Code で使う定型依頼文は [`prompts/README.md`](../prompts/README.md) にあります。テンプレート自体の設計・変更の記録は [`docs/design-history.md`](design-history.md) を参照してください。
