# 設計・開発の履歴

この文書は、テンプレートの利用者や第三者が「何の依頼から、何を、なぜ追加したか」を追うための索引です。**Git のコミットは変更内容の証拠**ですが、参加者との会話や生成 AI の利用ログ全文を代替しません。以下の依頼内容は、このテンプレートを作る作業中の会話を要約したものです。「実装上の選択」は、その依頼を受けてテンプレートを作成した側の判断であり、参加者が個別に指定したものとは限りません。原文の完全な記録が必要な場合は、当該会話ログを別途参照してください。

履歴を確認するときは、各項目のコミット ID を `git show ［ID］` で開くと、実際の差分を見られます。ファイルごとの変更順は `git log -- ［パス］` で確認できます。

## 設計の対象

- 複数の AHC で使う実験記録、比較実行、集計、Claude Code 用の指示・定型依頼文を用意する。
- 大会ごとに変わる解法、公式ツール、採点式、入力、実験結果は、テンプレートの共通部分から分ける。
- 解法上の判断は参加者が行い、AI は適用されるルールの範囲内で実装と機械的な処理を補助する。
- 将来の正式な AI 利用ルールに合わせて、`AGENTS.md` と関連する指示・プロンプトを更新できるようにする。

## 構成上の主な判断

| 対象 | 現在の構成と理由 | 確認できる場所 |
|---|---|---|
| AI 利用ルール | 全文と AI 向け必須指示を `AGENTS.md` に置き、Claude Code から読み込む。更新時に本文の二重管理を避けるため | `AGENTS.md`、`CLAUDE.md` |

## 今後の記録方法

テンプレートを変更するたびに、この文書へ次の情報を追記します。未確認のことは「未確認」と記し、後から根拠を推測して埋めません。

1. 日付と変更の対象。
2. 参加者の依頼・判断。解法上の判断なら、その内容を参加者の言葉に基づいて記録する。
3. 実装者が選んだ、解法に影響しない構成上の方法とその理由。
4. 変更したファイル、関連する実験 ID、コミット ID。
5. 実施した確認と未検証事項。
6. AI の利用に関するログの保存先と提出管理。公開してよい範囲だけを書く。

大会固有の解法変更や採用判断は、大会側の `docs/solutions.md`、`docs/experiments/`、必要なら `docs/decisions.md` に残します。テンプレートの履歴と大会の解法履歴を混同しないためです。
